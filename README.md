# 東洋医学 学習スイート

国試学習・〇×問題集・暗記・経穴カルタ用音声・弁証／選穴支援・トレーニング検索の6アプリを、1つのホーム画面から起動できるようにまとめた統合 PWA です。ホームにカードを表示し、タップすると各アプリが全画面で開きます（iframe 方式）。

## 特長

- **6アプリを1か所に** — ホームのカードから各アプリへ分岐。「‹ ホーム」で戻れます。
- **個人IDの設定が必須** — 学校と学生番号を設定するまで、どのアプリも開けません（成績表が不要なら誕生日4桁でも可）。
- **オンライン専用** — 著作権管理のため、問題・経穴などのコンテンツは端末に永続保存しません（後述）。
- **学習履歴は端末内に保持** — 各アプリの学習履歴・カルテはコンテンツとは別に、端末内（localStorage / IndexedDB）に保存されます。
- **バージョンは1つに統一** — `version.json` で一元管理。更新は自動確認・自動適用で、更新ボタンはありません。
- **日付バージョン＋自動化** — push すると GitHub Actions が日付でバージョンを自動生成します（例 `2026.7.16-8d88f03`。同じ日に複数回更新したときだけ末尾に短いハッシュが付きます）。
- **学習データの集計** — 国試学習・〇×問題集の学習データを Google スプレッドシートへ送信し、成績分析アプリで閲覧できます（任意機能）。

### 本試験形式モードと本試験専用問題（国試学習）

本試験形式モードは、試験種別（はり師きゅう師 180問＝AM90＋PM90／あマ指 160問＝AM80＋PM80）を選び、次のいずれかから本試験の科目構成に従って抽出します。

- 年度を選んで出題（その年度内から科目別抽出）
- 全範囲からランダム出題（全年度から科目別抽出）
- **本試験専用問題** — `questions.json` で `examOnly: true`（日本語キー「本試験モードのみに出題」でも可）を付けた問題群

`examOnly` の問題は本試験モードのみに出題され、今日の演習・復習・科目別演習・検索からは除外されます。ドロップダウンには **`year` の値がそのままセット名として並ぶ**ため、セットを増やすときは `year` にセット名（例 `第35回予想問題①`）を入れて `examOnly: true` を付けた問題を `questions.json` へ追加します。

**1セット＝1試験種別 × 1セット名**です。配布版のセット構成は次のとおり（詳細はカタログを参照）。

| 配布版 | セット名 | 回数 |
|---|---|---|
| A版 | 第25-34回頻出問題 | 1セット × 2試験種別 ＝ 2回分 |
| B版 | 第1-34回頻出問題／第25-34回頻出問題／第35回予想問題①／第35回予想問題② | 4セット × 2試験種別 ＝ 8回分 |

## 個人ID（学校・学生番号）

**学校と学生番号を設定しないと、どのアプリも開けません。** カードをタップすると設定用のダイアログ（ゲート）が出ます。ホームの「個人ID設定（データ分析用）」からも設定できます。

- **学校**はプルダウン（`index.html` の `SCHOOLS` 定数。現在は `大阪行岡医療専門学校長柄校` の1件のみ。空欄は設けていません）。増やすときはこの配列に追記します。
- **成績表が不要な人は、学生番号の代わりに誕生日4桁（例：8月10日 → `0810`）**で登録できます。個人が特定されない値でも、端末内の学習記録と忘却曲線はそのまま機能します。なお `SYNC_ENDPOINT` が設定されている限り**学習データの送信自体は行われます**（誕生日4桁の場合、誰のものか判別できない行として `progress` に積まれるだけです）。
- 学生番号は**全角で入力されると半角へ自動変換**されます（`normalizeStudentNo`）。シート側は「学校名＋学生番号」で個人を判別するため、表記ゆれがあると別人の行になってしまうためです。
- **一度保存すると変更できません**（入力欄・保存ボタンがロックされます）。変更したい場合はホーム下部の「学習データをリセット」から再設定します。

### あとから学生番号に変更した場合

誕生日4桁などで登録したあと学生番号へ変更しても、**それ以前の日ごとの記録・時期をまたいだ比較（○→× の変化など）は成績表に作れません**。`full` で送られるのは各問題の**最終的な結果のみ**で、日ごとの履歴は端末に残っていないためです。累計の正答率・科目別の成績・想定点数は引き継げます。成績表を希望する予定があるなら、最初から学生番号で登録してもらってください。

### 初回設定直後のバックアップ確認

個人IDを保存した直後に「バックアップを読み込みますか？」というポップアップが出ます。先にアプリを起動すると、**その時点の（空の）学習データで `full` 送信が確定**してしまい、あとから復元しても復元分が送られないためです。復元を行うと `syncInitialDone` フラグが削除され、次回起動時に復元後のデータが送り直されます。

## オンライン専用（著作権管理）

著作権管理のため、このスイートは**オンライン専用**です。`sw.js` は network-only で、**キャッシュへの保存も参照も一切行いません**。

```js
// sw.js
self.addEventListener('fetch', event => {
  event.respondWith(fetch(req, { cache: 'no-store' }));
});
```

- 問題データ（`questions.json` 等）はアプリを開くたびにサーバーから取得し、その場限りで表示します。
- **オフラインでは起動・利用できません**（電車内・電波の弱い場所など）。これは著作権管理を優先した仕様です。
- 利用者の**学習履歴・カルテは端末内に保存**され、これとは別に保持されます。

## 学習データの保存場所

コンテンツは保存されませんが、利用者の学習データは端末内に残ります。

| 保存先 | 内容 |
|---|---|
| IndexedDB `StudyAppDB` | 国試学習：進度・メモ・出題除外・本試験セッション・設定 |
| IndexedDB `MarubatsuDB` | 〇×問題集：進度・設定 |
| localStorage `suite_student_info` | 学校名・学生番号（`{school, studentNo}`。学習データ送信時の個人IDに使用） |
| localStorage `suite_device_uuid` | 端末ID |
| localStorage `sync_queue_kokushi` / `sync_queue_marubatsu` | 未送信の学習データ（オフライン時の再送用） |

ホームの「全データをバックアップ」で JSON として書き出せます。

## 学習データの収集（任意機能）

国試学習・〇×問題集は、学習データを Google スプレッドシートへ送信できます。教員は `seiseki_app.html` で成績表を閲覧します。

### 送信のタイミング

| 種別 | タイミング |
|---|---|
| `full` | アプリ起動時に1回だけ。その端末の全学習データ（各問題の**最終的な**進度・メモ・出題除外。日ごとの記録は含みません） |
| `answer` | 通常モードで1問解くたび（差分） |
| `memoOrMute` | メモ保存・出題除外の切替時（解答数にはカウントしない） |
| `examFinished` | 本試験モードを解き終えたとき（結果まとめ＋各問題の進度） |

送信できなかった分は localStorage のキューに残り、次回起動時やオンライン復帰時に自動で再送されます。

`SYNC_FULL_VERSION`（各アプリ内の定数）を上げると、全端末が次回起動時に一度だけ `full` を再送します。送信内容やシート構成を変えたときに、既存データをシートへ入れ直すために使います。

### セットアップ

1. Google スプレッドシートを新規作成し、**拡張機能 → Apps Script** に `gas_code.gs` を貼り付ける
2. **デプロイ → 新しいデプロイ → ウェブアプリ**（実行するユーザー: 自分／アクセスできるユーザー: 全員）で発行された `/exec` の URL を控える
3. `apps/kokushi/index.html` と `apps/marubatsu/index.html` の `SYNC_ENDPOINT` にその URL を貼る
4. GAS エディタで **`setupAnalyticsKey()` を1回実行**し、実行ログに出た**閲覧キー**を控える
5. `seiseki_app.html` を手元のPCで開き、URL と閲覧キーを入力して読み込む

`gas_code.gs` を修正したときは、**デプロイ → デプロイを管理 → 編集（鉛筆）→ 新バージョン**で再デプロイしないと反映されません。

### 閲覧キーについて

アプリからの送信（`doPost`）は認証なしのブラウザ送信のため、デプロイは「アクセスできるユーザー: 全員」にせざるを得ず、URL を知っていれば誰でもアクセスできる状態になります。URL はアプリのソースに書かれており隠せません。

そのため、**読み出し（`doGet`）だけは閲覧キーを要求**し、全学生分のデータが誰でも読める状態を防いでいます。送信にキーは不要です（学生の端末にキーを置かないため）。

- キーはスクリプトプロパティに保存されるため、`gas_code.gs` を共有してもキーは漏れません。
- キーを忘れたら `showAnalyticsKey()`、作り直すなら `setupAnalyticsKey()` を再実行します。
- キーは URL のクエリとして送られるため、**閲覧に使った PC のブラウザ履歴に残ります**。共用 PC では使用後に履歴を消してください（成績分析アプリの「このPCに閲覧キーを保存する」をオフにもできます）。

### スプレッドシートの構成

| シート | 内容 |
|---|---|
| `raw_log` | 受信した生データを1操作＝1行で記録。`dateJST` 列で日別集計できる（監査・再集計用） |
| `progress` | 問題ごとの最新の進度。**学校名＋学生番号** × アプリ × 問題ID で1行に集約（正答率集計のベース。`deviceId` は参考情報で、行のキーには使いません） |
| `exam_results` | 本試験モードの結果サマリ（1回の受験＝1行） |

`progress` の更新は**マージ方式**です（送られてきた項目だけ上書きし、送られてこなかった項目は既存値を維持）。

## 学習データのリセット

ホーム下部の「🗑 学習データをリセット」で、国試学習・〇×問題集の学習データと個人ID（学校・学生番号）を削除します。「リセット」と入力すると実行されます。**学生番号を入力し直したいときは、ここからリセットします**（リセット後、次にアプリを開くと設定ダイアログが再び出ます）。

処理の順序には理由があります。

1. **アプリ（iframe）を破棄** — 非表示にするだけではアプリがメモリ上に持つ学習データが残り、次に1問解いた瞬間に古い値が書き戻されてしまうため
2. **学生番号・送信待ちキューを削除し、画面へ反映** — この後の処理で何があっても学生番号を再設定できる状態にするため
3. **IndexedDB の全ストアを空にする** — `deleteDatabase` は使いません。接続が残っているとブロックされたまま完了せず、以後そのDBへの `open` が全て待たされてアプリが起動しなくなるためです
4. **Cache Storage の全削除と Service Worker の登録解除** — 設定ごと初期化する操作のため、配信ファイルも取得し直させます
5. **自動で再読み込み**

リセット後は `SYNC_FULL_VERSION` の判定により、次回起動時に `full` が送り直されます。**スプレッドシートに送信済みのデータは削除されません**（端末内のみのリセットです）。

## 公開手順（GitHub Pages）

1. ファイル一式をリポジトリのルートに配置して push。
2. **Settings → Actions → General → Workflow permissions** で「**Read and write permissions**」を有効化（`version.json` の自動コミットに必要）。
3. **Settings → Pages → Build and deployment → Source** で「**GitHub Actions**」を選択。
4. main（または master）に push すると、ワークフローが
   1. `version.json` を日付で更新
   2. GitHub Pages へデプロイ
   を自動実行します。
5. 数十秒〜数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

## 更新のしくみ

- アプリ本体（HTML）やデータ（`questions.json` 等）を変更して push すると、`version.json` が日付で自動更新されます。**手動でバージョンを上げる必要はありません。**
- 利用者側は次のタイミングで `version.json` をサーバーへ確認します（`cache:'no-store'` で必ずネットから取得）。
  - ホームの起動時
  - バックグラウンドから復帰した瞬間（`visibilitychange`）
  - 起動中は30分ごと
- バージョンが変わっていれば、開いていたアプリを記憶したうえで自動的に最新版へ切り替えます（更新ボタンはありません）。
- オフライン時は何も起こりません（更新確認をスキップするだけで、ロックはしません）。

### 個別アプリだけ直したいとき

- 問題を増やすだけ → `apps/kokushi/questions.json` を編集して push。
- 本試験専用問題のセットを増やす → `apps/kokushi/questions.json` に `examOnly: true`・`year: セット名` を付けた問題を追加して push。
- 〇×問題を直すだけ → `apps/marubatsu/marubatsu_questions.json` を編集して push。
- アプリの見た目・動作を直す → 該当する `apps/＜アプリ＞/index.html` を編集して push。

いずれも push すれば日付バージョンが自動で上がり、利用者側に更新が届きます。

## 仕組みのメモ（iframe 方式）

各アプリは元のコードをほぼそのまま `apps/＜アプリ＞/` に配置しています。統合のために、各 `index.html` の先頭へ短いガードスクリプトを1つだけ追加してあります。これは「iframe 内で動くときだけ、そのアプリ独自の Service Worker 登録・キャッシュ操作・更新ボタンを無効化する」ものです（単体で直接開いたときは元のまま動作します）。キャッシュとバージョン管理を親（このホーム）に一本化し、アプリ同士の干渉を防ぐためのものです。

制作者情報とバージョンは**統合ホームにのみ**表示されます。各アプリ個別の更新ボタン・バージョン表示は撤去しました。

## ローカル確認

`file://` で直接開くと Service Worker は無効ですが、ホームと各アプリの基本動作は確認できます。PWA 動作まで確認するには簡易サーバーを使ってください。

```
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```
